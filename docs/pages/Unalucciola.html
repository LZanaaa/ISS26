Firefly

Introduction

Definere un modello qak di un sistema firefly che simula il comportamento di una lucciola.

Requirements

  1. La lucciola deve accendersi per un tempo T poi spegnersi in modo ciclico.
  2. Il sistema dev'essere basato su autori.
  3. Gli attori devono poter notificare il comportamento della lucciola all'esterno

Requirement analysis

Classi:

  • Firefly: lucciola, modellata come QActor in Qak. Ha due stati Accesa e Spenta. Gli stati sono definiti da una macchina a stati interna all'attore

Problem analysis

Il ciclo di accensione/spegnimento di una lucciola può essere modellato come lo stato di un actor che alterna tra “acceso” e “spento” a intervalli di tempo variabili. La ripetizione del ciclo di lampeggio è gestita da una transizione che torna allo stato “flash” dopo un certo tempo.

Test plans

Il test di firefly avviene tramite un mock observer 

                QActor mockobserver context ctxfirefly {
                    [# var FlashDur = 0L #]

                    State s0 initial {
                        println("$name | In attesa") color cyan
                    }
                    Transition t0 
                        whenMsg flash -> handleFlash
                    
                    State handleFlash {
                        onMsg( flash : arg(X, Y, T) ){
                            [# 
                                var X = payloadArg(0) 
                                var Y = payloadArg(1) 
                                FlashDur = payloadArg(2).toLong() 
                            #]
                            println("$name v2 | Vedo luce da Lucciola") color yellow
                        }
                    }
                    // Il mock "rimane acceso" simulando lo stesso tempo della lucciola
                    Transition t1 whenTimeVar FlashDur -> fineFlash
                    
                    State fineFlash {
                        println("$name | SPenta") color magenta
                    }
                    Goto s0 
                }
